# Block unsafe Markdown before the editor

Paperbranch will classify a document's Markdown before loading it into the formatted editor, and will block formatted editing entirely for a document containing front matter or mathematical notation instead of loading it. The editor proof found that Milkdown's commonmark parser has no dedicated node for either construct and silently reinterprets their delimiters as different supported content on serialize (front matter becomes a heading and a thematic break; math source is mutated by commonmark escaping), which violates the requirement that Paperbranch never silently convert an unsupported construct into different supported content. Testing TOAST UI Editor as the required fallback found the same failure plus additional data loss (dropped raw HTML, corrupted footnote definitions), so switching editors does not resolve it. Neither building custom inert editor nodes for front matter and math nor accepting the mutation as a documented limitation was acceptable for the first version, so Paperbranch instead detects these two constructs ahead of the editor, using the real Markdown AST (via `remark-frontmatter` and `remark-math`) rather than pattern-matching raw text, and refuses to load a document that contains either one. Raw HTML, footnotes, Mermaid diagrams, and unrecognized syntax are not blocked: the proof found Milkdown keeps all four intact through a load-serialize round trip, so those remain admitted and behave as ordinary unsupported-but-safe content. Milkdown is the selected editor for Paperbranch on the strength of this admission seam, not on its own; see `editor-proof/PROOF_REPORT.md` for the full comparison.
